Lesson 535.7 - Port Map, As-Built and Hand-Off

How an installer writes down what each outlet is connected to and which network it serves, checks the records against the labels and the equipment, and hands them to a named person with every credential kept out.

Kestrel Communications has turned up the network on the Level 2 installation mock-up of the Harlow Street Operations Center, project HSOC-26-014. Before the owner, Calder Regional Services, accepts it, Kestrel hands Calder’s network team a record of every outlet: what it is connected to, which network it serves, what was tested, and what is still open.

Six months from now, a technician who has never been in the building arrives with a work order naming an outlet and a device. Which switch port serves that outlet? Which network is it on, and what address does the device hold? Was the run tested, and by whom? The answers are whatever the records say.

The worked examples on this page come from other jobs, not from the mock-up.

The identifier joins the records

One outlet carries the same identifier on its faceplate, in its port map row, in the as-built, and on its line in the test record. Where two records name it differently, a reader cannot move from one to the other.

ANSI/TIA-606-D, from the American National Standards Institute (ANSI) and the Telecommunications Industry Association (TIA), treats identifiers, labels, and records as one subject. It sets out how an identifier is built and leaves the values to the site. It expects the site to keep its labels and its records in step. Before you read a label or write one, find the scheme it was written to. On the mock-up, section 4 of the Kestrel Network Plan gives it.

Find out, too, where each record lives and which ones you may change. A correct record written into the wrong file leaves the site with two records that disagree.

535.7.2 A port map row and its network fields

A port map row ties an outlet to the switch port that serves it and to the network that port puts it on.

The cabling fields of a row were fixed when the building was cabled: the outlet label and the panel port. The network fields describe what the outlet serves today. Each is read off the equipment.

The fields of a port map row for an outlet in service.
FieldWhat it holds
Outlet and panel portThe labels at each end of the run
Switch and portThe switch’s label and the port, as the switch names it
VLANThe VLAN the switch port is in
Device and MAC addressWhat is connected, and the MAC address the switch learned on the port
IP address and methodThe device’s IP address and mask, and how it got them: from a Dynamic Host Configuration Protocol (DHCP) server, or set by hand (static)
Gateway and DNSThe default gateway and the Domain Name System (DNS) servers the device uses
State, last changed, test referenceIn service, spare, reserved, or retired; the date the row was last written; where the test result for the run is kept
Part of a port map on another job: telecommunications room TR-2, panel C.
OutletPanel portSwitch, portVLANDevice, MAC addressIP address, methodState
3B-05C / 05SW-2, Gi0/17140Laptop, aa11.bb22.cc44192.168.70.131 /24, DHCPIn service
3B-06C / 06SW-2, Gi0/18140Printer, aa11.bb22.cc55192.168.70.20 /24, staticIn service

The extract leaves out the gateway, DNS, last-changed, and test-reference columns to fit the page. An address is written with its mask in short form: /24 means that the first three numbers of the address name its network. Outlet 3B-07 is terminated and tested and waits for a device. Outlet 3B-08 stays in the map as retired, so that the next technician does not patch it expecting a working run.

Rules for the whole map

  • No two rows name the same switch port. A port serves one outlet at a time. Two rows naming one port mean one of them is out of date; the map cannot say which.
  • A position taken out of service keeps its row, with its state changed to retired and dated.
  • Write down the old value before you type the new one, in the change log or with the job paperwork. Write it at the outlet, not at the end of the day.
  • A spare position gets a row, marked spare. A spare position with no row looks to the next technician like a position that does not exist.

535.7.3 Reading each value off the equipment

Each value in a row is read on one platform. The evidence for it names that platform, so a reader knows where to read it again.

Figure — Where each value of a row is read
Text description of this diagram

The diagram is titled Where each value of a row is read, and shows three columns. Windows, ipconfig /all: MAC address (Physical Address); IPv4 address and mask; DHCP or static (DHCP Enabled); default gateway; DNS servers. IOS, the switch console: the port the MAC address is on; the VLAN it arrived in; the port’s Status and Vlan; read with show mac address-table address and show interfaces followed by the port and status.

UniFi Network application: a switch port’s client MAC address; the port’s native network; each network’s VLAN ID; read in the port view and in Settings, Networks; the names vary by version.

One MAC address, two forms

A MAC address is 12 hexadecimal digits, 0 to 9 and a to f. Windows writes them in six pairs separated by hyphens; a Cisco switch writes them in three groups of four separated by dots. AA-11-BB-22-CC-44 in ipconfig /all is aa11.bb22.cc44 on the switch.

Reading the switch port

With the laptop sending traffic, for example running ping -t to its gateway, look up its MAC address on the switch with show mac address-table address (on older releases, show mac-address-table address), then read that port’s own status line. In show interfaces <port> status, the port name takes the switch’s form: Gi0/17 on a Catalyst 2960G, Gi1/0/17 on a Catalyst 3750G.

show interfaces Gi0/17 status — one port on another job’s switch
SW-2> show interfaces Gi0/17 status

Port      Name               Status       Vlan       Duplex  Speed Type
Gi0/17                       connected    140        a-full a-1000 10/100/1000BaseTX
  • Status connected — the port has a link. Vlan 140 — the VLAN that goes in the row.
  • Duplex and Speed — how the link came up, negotiated (a-) at full duplex and 1000 megabits per second (Mbps). Name is a description typed on the port; Type is what the port is built for.

A camera’s row

A camera cannot be read with ipconfig. Take its IP address and addressing method from the card kept with the camera, and prove the address with a ping reply. The controller’s client list gives the camera’s MAC address and port, and may show no IP address for it.

Labeling the evidence by platform

Caption each screenshot or photograph with its platform and what it shows: Windows: ipconfig /all, Ethernet adapter; IOS: show interfaces Gi0/17 status; UniFi: Networks list. A reader checking a value later knows which screen to open.

535.7.4 The as-built and the test record

The as-built says where things are. The test record says what a tool showed, on what day, and claims nothing more.

A location someone can walk to

An as-built entry for an outlet or a device gives its location and its labels:

  • The space, such as a room or a wall.
  • The position in it, measured from something that will still be there next year. A position measured from a desk fails the week the desks move.
  • How it is mounted, such as on a wall, a ceiling, or a pole.
  • Which way it faces, for a camera or a directional antenna.
  • The label at each end of the run.

The as-built carries a date and a revision mark, so that a reader can tell it from the drawing it replaced. A device and the outlet it is connected to are two positions; record both.

One line of a test record

What one line of a test record carries.
FieldWhat goes in it
RunThe outlet and the panel port it lands on
TestEach test named: wiremap, length. The word tested alone does not say which
ResultWhat the tool showed, as it showed it
ToolThe make and model
Date and taken byWhen the reading was taken, and the name of whoever held the tool
LimitationWhat the test does not show, or none

Verified is not certified

A wiremap tester, a verifier, shows how a run is wired: each conductor reaching its pin, and the length. A certification tester measures how the run carries a signal and reports it against the limits of a named category. A line built from a wiremap may say the run is wired correctly, on the day it was tested. It may not say the run meets a category, because nothing in it measured one. The wiremap tester on the mock-up also does not detect a split pair, a fault in which one signal pair is made of wires from two different twisted pairs. Write that on the Limitation line.

A site that wants a category on the record is asking for a certification test, with a different instrument.

535.7.5 Checking labels against rows

A row’s identifier appears on the hardware in more than one place. Check each place.

An outlet’s identifier is on its faceplate. The panel port it lands on carries a label in the rack. Many sites also label the cable at each end, behind the faceplate and behind the panel. The switch port carries no site label: check its row by reading the switch.

Figure — One row, checked in the places it names
Text description of this diagram

The diagram is titled One row, checked in the places it names (another job). At the top, a row reads 3B-05, C / 05, SW-2 Gi0/17, VLAN 140. Lines lead from it to three boxes. Two are the faceplate at the outlet, 3B-05, and the panel port label in the rack, C / 05. A dashed line leads to the third, a dashed box: the switch port, which has no site label and is read at the switch.

Below, two boxes give the two directions of a check. Record to hardware finds a label missing, wrong, or unreadable. Hardware to record finds a label, an outlet, or a port with no row.

Run it in both directions

  • Record to hardware. Take each row and find the labels it names. This finds a blank faceplate, a fallen label, or a panel port labeled as something else.
  • Hardware to record. Read every label you can see and find its row. This finds what the records left out: an outlet added later, a panel port labeled and never recorded.

Start from the records, because they are a finite list and tell you where to go. Take the second direction on the way back.

Recording a difference

Where a label agrees with its row, mark the row agrees. A label that differs gets an exception line in four parts.

The four parts of an exception line, with an example from another job.
PartExample
The positionOutlet 3B-06, panel port C / 06
What the record saysFaceplate label 3B-06
What was foundFaceplate blank; 3B-06 handwritten on tape inside the cover
Where and whenRoom 3B, 2026-06-18, 10:20, initials J.R.

Where a label is missing or unreadable, a tone generator and probe identify the run before you write anything. Making or replacing a label is a separate task; where the work order does not assign it, the exception line records the difference and the decision goes to the record owner. A change to a cord or a setting is never part of a label check.

A label check compares two records, the labels and the rows, not the building. Both can agree and both be wrong where both were copied from the same drawing. Reading the switch catches part of that error. Toning the run settles the rest.

535.7.6 Drafting the records with an AI assistant

An AI chat tool turns a day’s field notes into a site’s columns in seconds. That conversion is also where a wrong value gets in.

Field notes are short lines, written standing up, in the order you walked the job. The site wants rows in a fixed column order, worded the same way throughout. An AI tool such as Microsoft Copilot does that conversion well: it orders columns, words every row alike, and puts dates and identifiers into one format.

It also tends to complete every table it is given. Asked for a finished port map, it fills a cell it has no value for with a value that fits the pattern of the cells around it. The invented value looks the same as the ones it read. It knows nothing about the building beyond your notes, so every value it returns came from your notes or from nowhere.

Before you paste anything

Port maps, floor plans, MAC addresses, and IP addresses describe how a building is wired and how to reach its equipment. Many sites restrict them. The record owner, the contract, and your employer’s policy on approved tools decide whether a site’s data may go into an AI tool, and which account to use. Settle it before the job. Where the answer is no, do the conversion by hand. No credential goes into a prompt under any answer.

How to ask

  • The column names, in the site’s order. Without them the tool chooses its own columns.
  • Your notes, unedited. Tidying them first hides the gaps you want reported back.
  • An instruction about gaps. Tell the tool that a cell with no value in the notes stays empty and goes on a list of gaps. Without it, the tool fills the gaps.

What a day of notes does not hold

One technician’s notes from one panel on another job, for a port map whose columns are Outlet, Panel port, Switch port, VLAN, MAC address, IP address, Method, and State:

Field notes — TR-2, panel C, another job
3b-05 c/05 sw2 gi0/17 vlan140 aa11.bb22.cc44 .131 dhcp
3b-06 c/06 gi0/18 printer .20 static
c/07 term, not patched, tested ok
c/08 dead run, do not use
3b-05 retest 14:20 after cord swap, 4/4 ping

The 3B-06 line has no VLAN and no MAC address, and names no switch. The C / 07 and C / 08 lines have no outlet, and give their state in words the State column does not use. The two 3B-05 lines may be one row or two. A tool asked for full columns fills each of these gaps. A VLAN number is easy to fill plausibly and hard to catch.

Checking the draft, row by row

Read each row of the draft against your notes, value by value. Correct any value that differs from the notes, and delete any value the notes do not hold. Mark each row verified or corrected, list each change you made, and list every empty cell with why it is empty and what would fill it. The faults to look for are a value that is not in the notes, two notes merged into one row, and a location that reads well and names a different place. The name on the record is yours, not the tool’s.

The as-built from the same notes

The as-built schedule is drafted the same way. Give the tool its columns (the space, the position, how each item is mounted, which way it faces, and the label at each end) and your location notes, with the same instruction about gaps. A position the notes do not measure stays empty and goes on the list. Check each row against the notes as you checked the port map.

535.7.7 Reading the records back against the bay

The last check holds the records against the installation itself: read the record, say what you expect to find, then look.

If you read the hardware first, you read the record already knowing the answer, and tend to mark it agreed. Write the expected value down, then read the outlet, the panel port label (or a photograph of it you took that day), or the switch, and mark whether it agrees. A difference becomes an exception line, in the four parts used for labels.

What the closing check covers

  • Every row names a position you can find, carrying the label the row gives.
  • Every outlet and device in the as-built has an identifier, and that identifier has a row.
  • Every run you worked on has a line in the test record, and every line names a run that exists.
  • Every switch port named in a row reads what the row says: its Status and Vlan in show interfaces status, or its network in the controller.
  • No two rows name the same switch port.
  • Every value in the records traces back to a reading or a label in your notes.

The check does not show that a run lands where its row says. Proving that means toning or tracing the run, which is its own task. Where a label and a row agree and you have reason to doubt both, say so in the record rather than marking it agreed.

Write down a check that found nothing, with its date, what it covered, and your name. With no record of it, the next person cannot tell that it happened.

535.7.8 Credentials and the hand-off

A hand-off goes to a named person on a named day. It carries no password, passphrase, or sign-in name.

Credentials stay out

A record is copied, forwarded, and kept for years, so anything in it is readable by people the installer never meets. On the mock-up, section 6 of the Kestrel Network Plan sets the rule: passwords, the wireless passphrase, and controller sign-in details never appear in a record, a screenshot, a photograph, or a prompt to an AI tool.

  • Before a screenshot, close or crop out any window or field that shows a sign-in, including the account name in the corner of a controller page.
  • In the record, state that a credential was used, never what it is: signed in with the site account.
  • In a prompt, paste readings, never sign-in details.

Where a credential appears in a record by mistake, tell the record owner. Deleting it from your copy does not remove it from the copies already sent. The owner decides whether to change the credential.

The hand-off note

The records go with a covering note. Read it back as the person receiving it: it should say what state the installation is in, what still needs doing, and who to call.

The parts of a hand-off note.
PartWhat it carries
Handed toThe person receiving it, and the date
What is installedEach outlet by its label, with its state
What was testedThe test, the tool, the date, and who held the tool, claiming no more than the test showed
What was foundEvery exception line
What is outstandingAnything unfinished, with what it needs and who has to act, including every run not tested
What is escalatedAny finding whose correction would change a setting no work order assigns, or move a rack cord where the work order does not allow patching or to any port other than the one the record or work order names. Each goes with its evidence and the decision needed
Who to callNames and contacts

Record a position you did not check as not checked, never as working. A row filled in from the work order, on the assumption that it ought to be right, reads the same as a row read off the hardware. It can send the next technician to the wrong place with confidence.

Accepted means a named person has said they hold the records. Until then, the records and anything missing from them are still the installer’s.

Lesson 535.7 · Section 3 Wrapping Up

535.7.9 What you covered

Read each value off the equipment, write the three records, check them against the labels and the bay, and hand them to a named person with every credential kept out.

The records you leave behind

The port map says which switch port serves each outlet, which network it is on, and what device is on it. The as-built says where each outlet and device is and how each is labeled. The test record says what each run measured, when, with which tool, and who took the reading. One identifier, built to the site’s scheme under ANSI/TIA-606-D, joins all three. A row in service carries the switch and port, the VLAN, the device with its MAC address, its IP address and how it got it, its gateway and DNS servers, and its state. No two rows name one switch port, a retired position keeps its row, and the installer writes down the old value before the new one.

Windows gives the laptop’s MAC address, IP address, mask, gateway, DNS servers, and DHCP state. IOS gives the port a MAC address is on and the port’s VLAN. The UniFi Network application gives a Power over Ethernet (PoE) port’s client, its native network, and each network’s VLAN ID. Each piece of evidence names its platform; a camera’s IP address and method come from its card. A wiremap verifies wiring and certifies nothing. The test record says what each test does not show.

Proving the records and handing them over

Check labels in both directions: record to hardware finds a wrong or missing label, and hardware to record finds what the records left out. Each difference becomes an exception line: the position, what the record says, what was found, and where and when. Give an AI tool unedited notes and the site’s columns, for the port map and for the as-built, and tell it to leave empty cells empty and list them. Then check every row against the notes and mark it verified or corrected. In the closing check, read the record first, then the bay and the switch. The hand-off note names the recipient and the date, what is installed, tested, found, outstanding, and escalated, and who to call. No password, passphrase, or sign-in name appears anywhere in the records, the screenshots, or a prompt.
