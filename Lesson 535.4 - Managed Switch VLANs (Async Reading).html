How an installer reaches a managed switch’s command line through its console port, reads which Virtual Local Area Network (VLAN) each port is in, places a port in a VLAN, and puts the switch back the way it was found.

A building owner wants the cameras, the door controllers, and the office computers kept apart, on the same switches. The network team separates them with VLANs: each switch port belongs to one VLAN, and the switch passes traffic only between ports of the same VLAN. The installer connects each device to the port the plan gives it, and checks at the switch that the port is in the VLAN the plan names.

535.4.1 One switch, several networks

Lesson 535.4

Managed Switch VLANs

A managed switch divides its ports into Virtual Local Area Networks (VLANs). It passes traffic only between ports of the same VLAN. An installer reaches the switch’s command line through its console port, reads which VLAN each port is in, and changes a port only where a work order assigns it. The installer undoes every change before leaving the switch.

5 sections  ·  11 topics  ·  11 activities

By the end of Lesson 535.4 you will be able to
  • Access the switch command line through a console connection.
  • Create a VLAN.
  • Assign a switch port to a VLAN.
  • Test reachability between two laptops on the same VLAN and on different VLANs.
  • Recognize the configuration tasks assigned to the network team.
  • Restore the switch ports to their starting state.

Out of the box, a switch keeps all its ports in one network: every device on it can reach every other.

A switch moves frames, the units of data on a local network, between its ports. A frame addressed to every device at once is a broadcast. A switch sends a broadcast out of every port in the same network as the port it arrived on. The ports that receive one another’s broadcasts form a broadcast domain. Out of the box, every port of a Catalyst switch is in VLAN 1, so the whole switch is one broadcast domain.

One broadcast domain suits a few devices. In a commercial building it lets a camera, a door controller, a payment terminal, and a visitor’s laptop reach one another. A faulty device that floods the network with broadcasts slows every device on the switch. Separate switches for each group would keep them apart, at the cost of more hardware and a cabling job for every change.

A VLAN gives the same separation as a setting. The network team assigns each switch port to a VLAN. Ports in one VLAN exchange frames and receive one another’s broadcasts. Ports in a different VLAN do the same among themselves. The switch passes no frame from one VLAN to the other. One switch then behaves as several separate switches.

535.4.3 The console connection

A managed switch has no screen or keyboard. A console cable connects it to a laptop, which supplies both.

The console port of a switch accepts a terminal, and nothing else. A console session carries your keystrokes to the switch’s command line and its replies back, with no IP address. It does not depend on the switch’s network settings, so it works on a switch whose network settings are wrong or whose ports are all shut down. On the Catalyst 3750G and 2960G, the console port is an RJ45 socket labeled CONSOLE, on the front or the back depending on the model. It looks like a network port; a patch cord in it does nothing.

The serial settings

The laptop and the switch must agree on how fast to send and how to frame each character. Most network equipment uses one set of serial settings, written 9600 8-N-1: 9600 bits per second, 8 data bits, no parity bit, and 1 stop bit, with flow control off. In PuTTY, select Serial on the Session page, enter the COM number under Serial line, and check that Speed reads 9600, its default. The other values are under Connection > Serial. PuTTY’s defaults are 8 data bits, 1 stop bit, and no parity. Its default Flow control is XON/XOFF: change it to None.

When the window stays blank, or shows symbols

  • A blank window is normal. The switch prints nothing until you press Enter; then a prompt appears.
  • Still nothing after Enter: check, in this order, that the cable is seated at both ends, that the COM number is the one Device Manager shows, that the speed is 9600, and that flow control is None.
  • Unreadable symbols: the connection works, but the two ends disagree on the speed. Set the speed to 9600.
  • A password prompt: a console can be protected by a password. On a switch the network team owns, enable usually asks for a password as well. Call the person who holds it to type it. Never write a switch password down. Keep it out of every screenshot.

Lesson 535.4 · Section 2 Reaching the Command Line

535.4.4 Modes and prompts

The switch’s command line has modes, and the prompt states which one you are in.

Each mode accepts its own set of commands. The prompt starts with the switch’s name, set by the network team (Switch on an unnamed switch), and ends with a symbol or a bracketed word that names the mode. A command typed in the wrong mode is rejected.

The command line modes used on this page, the prompt of each, how you enter it, and what it is for. NG-SW2 is the name of a switch on another job.
PromptModeHow you enter itWhat it is for
NG-SW2>User EXECA console session usually starts hereA few read-only commands
NG-SW2#Privileged EXECenableEvery show command; also saving and restarting, which are not an installer’s to do
NG-SW2(config)#Global configurationconfigure terminalSettings for the whole switch, such as creating a VLAN
NG-SW2(config-vlan)#VLAN configurationvlan and a numberSettings for that one VLAN, such as its name
NG-SW2(config-if)#Interface configurationinterface and a port nameSettings for that one port, such as its VLAN

exit steps back one mode. end leaves configuration from any configuration mode and returns to #, where the show commands run. disable returns from # to >.

Read the prompt before you press Enter. Some commands are accepted in more than one mode and act on whatever that mode governs: shutdown at a (config-if)# prompt shuts down that port.

Help at the command line

  • ? lists the commands valid at the prompt, or the ways to finish a command you have started.
  • Tab completes a word you have started; nothing completes if the word is misspelled.
  • The Up arrow recalls an earlier command.
  • A command can be shortened while it stays unambiguous: conf t for configure terminal. Type commands in full while you learn them.

Error messages

  • % Invalid input detected at '^' marker.: the switch did not recognize the word the caret points to: a typing error, or a command that does not belong in this mode.
  • % Incomplete command.: the command needs more, such as a number or a port name. Recall it with the Up arrow and add ? to see what it needs.

A rejected command changes nothing on the switch.

Match each prompt to its mode.

535.4.5 Reading the switch before you change it

show interfaces status and show vlan brief list every port’s name, state, and VLAN, and every VLAN on the switch. Record both before you type a configuration line.

Port names

A work order names a port by its number on the switch. The switch names it by type and position. The form differs between models. On a Catalyst 3750G, port 7 is GigabitEthernet1/0/7, shortened to Gi1/0/7: switch 1 in a stack, module 0, port 7. On a Catalyst 2960G, port 7 is GigabitEthernet0/7, or Gi0/7: module 0, port 7. A port name in the wrong form is rejected. A name in the right form for the wrong port is accepted, and the lines that follow change another device’s port. Read the names on the switch in front of you.

show interfaces status: an eight-port Catalyst 2960G on another job
NG-SW2# show interfaces status

Port      Name               Status       Vlan       Duplex  Speed Type
Gi0/1     Uplink to core     connected    trunk      a-full a-1000 10/100/1000BaseTX
Gi0/2                        connected    140        a-full a-1000 10/100/1000BaseTX
Gi0/3                        connected    140        a-full  a-100 10/100/1000BaseTX
Gi0/4                        notconnect   140          auto   auto 10/100/1000BaseTX
Gi0/5                        connected    1          a-full a-1000 10/100/1000BaseTX
Gi0/6                        notconnect   1            auto   auto 10/100/1000BaseTX
Gi0/7                        notconnect   1            auto   auto 10/100/1000BaseTX
Gi0/8                        disabled     1            auto   auto 10/100/1000BaseTX
  • Port: the switch’s own name for each port, in the form to type. Name: a description the network team may give a port; blank on most.
  • Status: connected means a device is on the far end and a link has formed. notconnect means the port is on and no link has formed (nothing plugged in, a device switched off, or a fault in the cabling). disabled means the port is shut down in the configuration; nothing at the outlet brings it up.
  • Vlan: the VLAN the port is in. trunk marks a port that carries several VLANs to another switch.
  • Duplex and Speed: a-full and a-1000 mean full duplex, traffic both ways at once, at 1000 Mbps. The a- prefix means the two ends negotiated the value. auto appears where no link has formed. Gi0/3 links at a-100. If the device on it supports 1000 Mbps, a 100 Mbps link often points at a fault in the cabling. Type: the kind of port, here copper at 10, 100, or 1000 Mbps.

The VLANs on the switch

NG-SW2# show vlan brief

  • Status: active for a VLAN in use.
  • Ports: the ports assigned to each VLAN. A trunk port carries several VLANs and is not listed: Gi0/1 does not appear.
  • 1002 to 1005: legacy VLANs present on every Catalyst switch, shown act/unsup. They cannot be deleted, and an installer leaves them alone.

535.4.6 Creating a VLAN and assigning a port

A VLAN belongs to the switch, so it is created in global configuration. A port’s VLAN belongs to the port, so it is set in that port’s interface configuration.

Every port starts in VLAN 1 unless someone has assigned it to another. The work order below, from another job, asks for a VLAN for door controllers and for one port in it.

Creating VLAN 150 and assigning port Gi0/6: another job
NG-SW2> enable
NG-SW2# configure terminal
Enter configuration commands, one per line.  End with CNTL/Z.
NG-SW2(config)# vlan 150
NG-SW2(config-vlan)# name DOORS-150
NG-SW2(config-vlan)# exit
NG-SW2(config)# interface gigabitethernet 0/6
NG-SW2(config-if)# switchport access vlan 150
NG-SW2(config-if)# end
NG-SW2#
*Mar  1 00:12:34.567: %SYS-5-CONFIG_I: Configured from console by console
  • enable and configure terminal: up to privileged EXEC, then into global configuration. The switch answers with a line saying commands are entered one per line, and that Ctrl+Z, like end, leaves configuration.
  • vlan 150: enters the configuration of VLAN 150. If the VLAN does not exist, the switch creates it when you leave VLAN configuration mode.
  • name DOORS-150: gives the VLAN a name a person can read. Use the name the work order or the site’s scheme gives.
  • interface gigabitethernet 0/6: selects one port. Every line after it applies to that port until you leave.
  • switchport access vlan 150: places the port in VLAN 150. The change takes effect when you press Enter, on whatever device is connected to the port.
  • end: back to #. The %SYS-5-CONFIG_I line is a log message recording that the configuration was changed from the console. The switch puts its time stamp in front of it; the time shown depends on the switch’s clock.

Then check: run show vlan brief, and confirm that VLAN 150 is listed with its name and that Gi0/6 is listed against it, no longer against VLAN 1.

What the switch does without asking

  • It creates a missing VLAN. On a switch that keeps its own VLAN list (topic 535.4.8 explains when a switch does not), typing switchport access vlan 170 with no VLAN 170 on the switch makes it print % Access VLAN does not exist. Creating vlan 170. The switch then creates VLAN 170 with a default name, VLAN0170, and assigns the port to it. Check the VLAN number against the work order before you press Enter.
  • It applies each line at once. There is no confirmation step. A line typed under the wrong interface changes that port, and the device on it, the moment you press Enter.

To undo a line, type it again with no in front. no vlan 150 in global configuration deletes VLAN 150. no switchport access vlan in interface configuration returns the port to VLAN 1, as does switchport access vlan 1.

535.4.7 Testing reach across VLANs

Two laptops on ports of the same VLAN reach each other through the switch. On ports of different VLANs, they do not.

A switch sends a frame only to ports in the VLAN of the port the frame arrived on. Within that VLAN, it chooses the port by the frame’s destination Media Access Control (MAC) address; it does not use the IP addresses inside the frame to decide. A frame reaches another VLAN only through a router, or through a switch the network team has set up to route between VLANs. Each VLAN is normally its own IP subnet, with its own gateway. The network team decides which VLANs may reach which.

Showing reach, and showing its absence

Test from a laptop on each port, with the ports in the VLANs the test calls for:

  • Ping the other laptop’s IP address, then run arp -a.
  • A reply from the other laptop’s IP address shows reach. So does an arp -a entry for that IP address with type dynamic. Before it pings, the laptop asks for the other laptop’s MAC address with an Address Resolution Protocol (ARP) request. Windows Defender Firewall blocks an incoming ping by default but not ARP, so the entry shows that the other laptop answered through the switch even where its ping timed out.
  • A Request timed out. line, or a Destination host unreachable. line carrying your own IP address, with no dynamic entry for the other laptop, shows no reach.

Record the result as the screen shows it, not as you expected it.

After a port changes VLAN, the switch may hold the port for ~30 s, while it checks the new VLAN for loops, before the port passes traffic. A loop is a second path between switches, which would let frames circle without end. Wait before you test. A test run too early can show no reach on a port that is about to work.

535.4.8 Saved and unsaved configuration

A switch applies each change at once, and keeps it after a restart only where it is saved.

The two configurations a Catalyst switch holds.
Running configurationStartup configuration
What it isWhat the switch is doing nowWhat the switch loads when it next starts
When it changesWhen you press Enter on a configuration lineOnly when someone saves
After a power lossLostKept
How it is readshow running-configshow startup-config

copy running-config startup-config, or its older form write memory, saves the running configuration as the startup configuration. On a switch the network team owns, saving is the network team’s decision. An installer making a temporary change does not save it. The installer undoes the change before leaving, so the running configuration again matches the startup configuration the network team left.

VLANs are also kept in a file of their own

On Catalyst switches, the list of VLANs is also written to a file in flash memory, vlan.dat, when a VLAN is created or deleted. This file is separate from both configurations. Whether a VLAN is still there after a restart depends on that file, the startup configuration, and the switch’s VLAN Trunking Protocol (VTP) mode. On a switch in VTP server mode, the default, a VLAN created and not saved survives a restart. Remove a test VLAN by deleting it with no vlan; leaving it unsaved does not remove it.

VTP mode

VTP lets switches share their list of VLANs over their trunks. Its mode decides what happens to a VLAN created on the switch:

  • Server: the switch can create VLANs and advertise them to the other switches of its VTP domain.
  • Client: the switch takes its VLANs from a server, and refuses a VLAN typed at its own command line.
  • Transparent: the switch keeps its VLANs to itself. A VLAN created there stays on that switch. After a restart, the switch takes its VLAN list from the startup configuration.

show vtp status shows the mode on a line beginning VTP Operating Mode. Some Cisco Internetwork Operating System (IOS) releases add a fourth mode, Off. The other lines of the output vary by release. VTP is set by the network team. A VLAN created on a switch in server mode can reach every switch in the domain.

Lesson 535.4 · Section 4 Restoring and Knowing Where to Stop

535.4.9 Putting the ports back

A restore returns each port you changed to the VLAN it started in, deletes any VLAN you created, and proves the result against the starting state.

The starting state comes from the show interfaces status and show vlan brief outputs you captured before the first change. In the example below, from another job, port Gi0/4 started in VLAN 140. The technician moved it into a test VLAN 170 that the work order allowed.

Restoring port Gi0/4 and deleting test VLAN 170: another job
NG-SW2# configure terminal
Enter configuration commands, one per line.  End with CNTL/Z.
NG-SW2(config)# interface gigabitethernet 0/4
NG-SW2(config-if)# switchport access vlan 140
NG-SW2(config-if)# exit
NG-SW2(config)# no vlan 170
NG-SW2(config)# end
NG-SW2# show vlan brief
  • switchport access vlan 140: returns the port to the VLAN the starting state shows.
  • exit: back to global configuration, where VLANs are deleted.
  • no vlan 170: deletes the test VLAN.
  • show vlan brief: the proof. Compare it, line by line, with the starting capture.

Return the ports before you delete the VLAN. A port whose VLAN has been deleted stays assigned to the deleted VLAN and passes no traffic until you assign it a VLAN that exists. show vlan brief then lists that port under no VLAN at all.

The restore is complete when show vlan brief shows every port you changed in its starting VLAN, and no VLAN you created. Leave the output on the screen for whoever checks your work. Do not save.

Lesson 535.4 · Section 4 Restoring and Knowing Where to Stop

535.4.10 Where your scope ends

An installer changes a switch port only where a work order assigns it. Everything else on the switch belongs to the network team.

A switch accepts far more commands than the few on this page. Some of them change how every switch in the building behaves, without an error message at the time. The line between the installer’s work and the network team’s follows how far a change reaches: a port assignment affects one device; a trunk or a VTP setting affects every device downstream of it. On the mock-up, section 5 of the network plan sets out what an installer may change.

Lesson 535.4 · Section 5 Wrapping Up

535.4.11 What you covered

Read the switch, change only the assigned ports, test what reaches what, and put the switch back as you found it.

VLANs on a managed switch

A VLAN divides a switch’s ports into groups. Ports in one VLAN exchange frames and broadcasts; the switch passes nothing between VLANs. Traffic between VLANs goes through a router, with each VLAN its own IP subnet. A VLAN is a port setting, invisible at the outlet. It changes neither the link nor the power on the port.

Reaching the command line

A USB console cable joins the laptop to the CONSOLE port. Device Manager shows its COM number. PuTTY runs Serial at 9600 8-N-1, flow control None. A blank window means the switch is waiting for Enter; unreadable symbols mean the wrong speed. The prompt names the mode: > User EXEC, # Privileged EXEC, (config)#, (config-vlan)#, and (config-if)#. end returns to #.

Restoring and knowing where to stop

Changes take effect at once and are kept in the running configuration; the startup configuration changes only when someone saves. An installer does not save. VLANs are also kept in vlan.dat, so leaving a test VLAN unsaved does not remove it. Return each port to its starting VLAN, then delete the test VLAN with no vlan, and compare show vlan brief with the starting capture. Trunks, VTP, routing, the address plan, wireless networks, saving, and software belong to the network team: hand them over with your readings.
