How an installer gives a laptop the Internet Protocol (IP) settings a device on the job expects, reads those settings back, and proves, in separate tests, that the laptop reaches another laptop, the gateway, and a device by name.

535.3.1 Four settings on every device

Lesson 535.3

IP Addressing for Device Access

An installer reaches a camera, a recorder, or a controller from a laptop. The laptop needs an Internet Protocol (IP) address on the device’s network, either leased from a Dynamic Host Configuration Protocol (DHCP) server or typed in from the address plan. The installer then tests a peer (another device on the laptop’s own network), the gateway, and a Domain Name System (DNS) name in separate commands. At the end of the task, the installer returns the laptop to DHCP.

A device on an IP network uses four settings to reach other devices.

D. Okafor briefs the teams at the start of the turn-up: “Every camera and controller on this job is found by its IP address. Your laptop reaches one only when it is on the right network, with an IP address no other device holds. Read what the laptop has before you change it.”

How a laptop uses the four settings

Before the laptop sends anything, it compares the destination IP address with its own, using the subnet mask. A destination on the laptop’s own network is reached directly, through the switch. Traffic for any other network goes to the default gateway, which forwards it. When you type a name instead of an IP address, the laptop first asks the DNS server for the IP address that belongs to the name.

535.3.2 Kinds of IP address

The first numbers of an IP address tell you what kind of address it is.

IPv4 addresses

An IP version 4 (IPv4) address is four numbers separated by dots, each from 0 to 255, such as 192.168.70.141. The cameras, controllers, and laptops on a low voltage job use IPv4. Most IPv4 addresses you meet fall into one of the kinds in the table.

Kinds of IPv4 address, the range of each, and where you meet it.
KindRangeWhere you meet it
Private10.0.0.0 to 10.255.255.255
172.16.0.0 to 172.31.255.255
192.168.0.0 to 192.168.255.255		Inside a building or a campus. These ranges are reserved for private networks, which any site may use. Routers on the internet do not carry them. The devices you install use private IP addresses.
PublicMost addresses outside the other ranges, such as 8.8.8.8, a DNS server run by GoogleOn the internet. Each public IP address is registered to one organization, usually through its internet provider.
Loopback127.0.0.0 to 127.255.255.255, usually 127.0.0.1Inside one device. A ping to 127.0.0.1 tests the laptop’s own network software and never leaves the laptop, so it proves nothing about the cable or the switch.
Link-local169.254.0.0 to 169.254.255.255On a laptop that asked for an IP address and received no answer. Topic 535.3.5 covers it.

IPv6 addresses

An IP version 6 (IPv6) address is longer: eight groups of up to four hexadecimal digits, separated by colons, such as 2001:db8:4a::25. A double colon stands for one run of groups that are all zero. With IPv6 turned on, as it is by default, Windows gives every connected network adapter an IPv6 address beginning fe80::, even on a network that uses only IPv4. ipconfig lists it. Recognize an IPv6 address when you see one; setting one is outside a turn-up task.

Match each address to its kind.

Lesson 535.3 · Section 2 Where the Settings Come From

535.3.3 A lease from DHCP

A laptop set to DHCP asks the network for its settings each time it connects, and holds them for a set time.

A DHCP server holds a pool: a range of IP addresses it may hand out on one network. When a laptop set to DHCP connects, the server gives it a lease. The lease carries an IP address from the pool, the subnet mask, the default gateway, the DNS server, and the time the lease lasts. Before the lease runs out, the laptop asks the server to renew it. The network team sets up the DHCP server and its pool. On many networks the gateway router also acts as the DHCP server.

A lease tells you which network the switch port has placed the laptop on. A laptop on an outlet patched to the wrong port, or to a port on the wrong network, still receives a lease, from the DHCP server of the network it is on. Compare the lease with the address plan before you trust it.

Reading the lease: ipconfig /all

In Command Prompt, ipconfig /all lists every network adapter in the laptop, with its settings. Find the section of the wired adapter, usually headed Ethernet adapter Ethernet.

  • DHCP Enabled: Yes means the adapter is set to ask for a lease; No means it uses a static IP address. Autoconfiguration Enabled: Yes means Windows may give the adapter a link-local address when no server answers.
  • Link-local IPv6 Address: the fe80:: address Windows gives every connected adapter. It plays no part in the checks on this page.
  • IPv4 Address and Subnet Mask: the IP address in use, marked (Preferred) by Windows, and its mask.

  • Default Gateway, DHCP Server, and DNS Servers: the router, the server that gave the lease, and the server that answers names. The DHCP Server line appears only when a server has answered.

To decide whether the lease is the one the plan expects, compare the IPv4 address with the plan’s network and with its DHCP pool. Topic 535.3.6 sets out how to tell whether two IP addresses are on the same network.

535.3.4 A static IP address

A static IP address is typed into a device by hand. The device keeps it until someone changes it.

A device that other devices must find at a known IP address usually has a static one: a camera, a recorder, a door controller, a printer. The network team assigns each static IP address from the address plan, outside the DHCP pool, so the DHCP server never hands the same IP address to another device.

An installer sets a laptop to a static IP address where the device to be reached sits on a network with no DHCP server (some camera networks have none), or where the task requires the laptop to be at a known IP address. A static setting on a laptop includes all four values: the IP address, the subnet mask, the default gateway, and the DNS server. A laptop reaching only devices on its own network can work without the gateway and the DNS server; leave those empty only where the task says so.

DHCP lease

  • Given by a server, from its pool.
  • May change each time the laptop connects.
  • ipconfig /all shows DHCP Enabled Yes, a DHCP Server line, and the lease times.
  • The server keeps two devices from holding the same IP address.

Static IP address

  • Typed in by hand, from the address plan.
  • Stays until someone changes it, on any network the laptop joins.
  • ipconfig /all shows DHCP Enabled No, and no lease times.
  • Nothing stops two devices from being given the same IP address, except the plan.

Duplicate IP addresses

When Windows finds another device already answering at the static IP address you entered, ipconfig /all marks the address (Duplicate) instead of (Preferred), and the laptop does not use it. Two devices sharing an IP address can both lose their connections. The other device may be a camera someone is watching. Return the laptop to DHCP at once. Ask the plan’s holder for another IP address: the network team, or on the mock-up the site lead. Choose a replacement yourself only where the plan’s holder allows it.

A static setting outlives the task

A laptop left on a static IP address carries it to the next network it joins. There it reaches nothing, or it takes an IP address the DHCP server later gives to another device. Record the starting settings before you change them. Set the laptop back to DHCP when the task ends.

535.3.5 169.254: no server answered

An IP address beginning 169.254 is one the laptop gave itself, because it asked for a lease and no DHCP server answered.

A laptop set to DHCP that receives no answer gives itself an IP address. Windows chooses one beginning 169.254, at random, with the mask 255.255.0.0. Windows keeps asking for a lease in the background. This is a link-local address, also called an APIPA address. A laptop with this address reaches only other devices with link-local addresses on the same network. It has no gateway, so it reaches nothing beyond them.

ipconfig /all: a laptop on another job with no answer from a DHCP server, other lines left out
C:\Users\installer> ipconfig /all

Ethernet adapter Ethernet:

   DHCP Enabled. . . . . . . . . . . : Yes
   Autoconfiguration Enabled . . . . : Yes
   Autoconfiguration IPv4 Address. . : 169.254.87.12(Preferred)
   Subnet Mask . . . . . . . . . . . : 255.255.0.0
   Default Gateway . . . . . . . . . :
  • Autoconfiguration IPv4 Address: the line Windows uses for a link-local address, in place of the IPv4 Address line.
  • Default Gateway: blank. There are no lease lines and no DHCP Server line, because no server answered.

What a 169.254 address tells you

A link-local address appears only when the adapter has a link. A laptop with no link at all shows Media State . . . : Media disconnected for the adapter instead, and no IP address. A 169.254 address therefore shows that the cable path carries a link from the laptop to a switch port, and that no DHCP server on that port’s network answered the request.

The causes sit above the cable. The switch port may be on a network that has no DHCP server, or the wrong network for the outlet. The DHCP server may be down, or its pool may be full. Record the address and the outlet. Type ipconfig /renew to make the laptop ask again. If ipconfig prints an error instead of a new IP address, unplug the laptop cord for ~5 s and plug it back in: Windows asks for a new lease when the link returns. If the address still begins 169.254, report it to the site lead: the DHCP server and the switch port’s network belong to the network team.

Lesson 535.3 · Section 3 Reading an Address Plan

535.3.6 Same network or different

The subnet mask decides which IP addresses share a network.

The /24 network

The mask 255.255.255.0 is written /24 for short. Written in binary, a mask is 32 ones and zeros (bits), eight for each of its four numbers. 255 is eight ones, so this mask begins with 24 ones. The first three numbers of the IP address name the network, and the fourth names the device. Many of the networks a low voltage installer meets use this mask. On a /24 network, two IP addresses are on the same network when their first three numbers match.

Pairs of IP addresses on /24 networks, and whether each pair is on the same network.
First IP addressSecond IP addressSame network?Why
10.31.6.1510.31.6.240SameThe first three numbers, 10.31.6, match
10.31.6.1510.31.7.15DifferentThe third number differs
172.20.4.9172.21.4.9DifferentThe second number differs

The network itself is written with a fourth number of 0 and its prefix length, such as 192.168.70.0/24. On every /24 network, two IP addresses are kept back from devices. The network address, with a last number of 0, names the network. The broadcast address, with a last number of 255, reaches every device on the network at once. That leaves the last numbers 1 to 254 for devices: 254 IP addresses, including the gateway.

Smaller networks

A network team sometimes divides a /24 into smaller networks, with a longer prefix and a mask whose last number is not 0. On these networks the first-three-numbers rule is not enough: two IP addresses with the same first three numbers can be on different networks. When you see one of these masks, take the network’s range from the address plan, or ask the network team. The calculation is the network team’s.

Lesson 535.3 · Section 3 Reading an Address Plan

535.3.7 Choosing an unused IP address

An address plan lists what each part of a network is for. An unused IP address is one the plan leaves free.

The network team keeps an address plan for each network: its network address and mask, its gateway, the range kept for network equipment, the DHCP pool, and the static IP address of each installed device. An installer reads the plan to find the IP address of a device, and, when the plan’s holder allows it, to choose an IP address for a new one.

Worked example

The extract below is from the camera network of a fictional depot. A new camera needs a static IP address.

Address plan extract: camera network, Northgate depot (fictional).
ItemPlan
Network192.168.80.0/24
Gateway192.168.80.1
Reserved for network equipment192.168.80.2 to 192.168.80.19
DHCP pool, for laptops192.168.80.50 to 192.168.80.149
InstalledRecorder 192.168.80.20; cameras 192.168.80.21, 192.168.80.22, 192.168.80.23, 192.168.80.25
Figure: The Northgate camera network, by the last number of the IP address
Text description of this diagram

The diagram, titled 192.168.80.0/24: what each last number is for (not to scale), is a bar divided into eight parts, read left to right by the last number of the IP address.

0, the network address. 1, the gateway. 2 to 19, reserved for network equipment. 20 to 25, installed devices, with 24 free. 26 to 49, free. 50 to 149, the DHCP pool. 150 to 254, free. 255, the broadcast address. A note reads: check a free IP address with the plan’s holder before a device takes it.

An IP address for the new camera must meet each of these conditions:

  • It is on the plan’s network: 192.168.80 as the first three numbers.
  • It is not the network address, 192.168.80.0, or the broadcast address, 192.168.80.255.
  • It is not the gateway, and not in the range reserved for network equipment.
  • It is outside the DHCP pool, so the server never hands it to a laptop.
  • It is not listed against an installed device.

192.168.80.24 passes: it is on the network, it is neither the network nor the broadcast address, it is above the reserved range and below the pool, and no device is listed against it. Write down the chosen IP address and the reason it qualifies. The plan’s holder confirms the choice and records the new device. A ping that gets no reply does not prove that an IP address is free: a device that is switched off, or that does not answer pings, still holds its IP address.

Lesson 535.3 · Section 4 Setting and Testing a Laptop

535.3.8 Setting a laptop in Windows 11

In Windows 11, you set the IP address, mask, gateway, and DNS server of each network adapter on one Settings page.

Before you change anything

  • Turn off Wi-Fi, so that every test you run goes through the wired adapter.
  • Record the starting settings: open Settings > Network & internet > Ethernet, and run ipconfig /all. The Ethernet page shows the IP assignment as Automatic (DHCP) or Manual.
  • If Windows asks for an administrator password when you save a setting, stop and tell the site lead. Do not enter a password you were not given.

Setting a static IP address

  1. In Settings > Network & internet > Ethernet, select Edit next to IP assignment.
  2. Choose Manual, and turn on IPv4.
  3. Enter the IP address the plan assigns you.
  4. Enter the Subnet mask, such as 255.255.255.0. Some Windows 11 versions ask for the Subnet prefix length instead: enter 24 for the same mask.
  5. Enter the Gateway and the Preferred DNS server from the plan. Leave Alternate DNS empty unless the plan gives one.
  6. Select Save. In Command Prompt, run ipconfig /all: DHCP Enabled reads No, and the IPv4 Address is the one you entered, marked (Preferred).

The same values can be set in the adapter’s older properties window (Windows + R, then ncpa.cpl), under Internet Protocol Version 4 (TCP/IPv4). That window may ask for administrator rights on a managed laptop.

The DNS server on its own

The Ethernet page also has a DNS server assignment row with its own Edit button. It lets a laptop take its IP address from DHCP and its DNS server from a manual entry. When you return a laptop to DHCP, check that this row also reads Automatic (DHCP); a manual DNS entry left behind sends every name to a server the next network may not have.

Restoring DHCP

  1. Select Edit next to IP assignment, choose Automatic (DHCP), and select Save. Check the DNS server assignment row.
  2. In Command Prompt, type ipconfig /renew to ask for a lease at once, then ipconfig /all. If ipconfig prints an error instead of a new IP address, unplug the laptop cord for ~5 s, plug it back in, and run ipconfig /all.
  3. Read the result: DHCP Enabled Yes, an IPv4 Address on the planned network, and a Lease Obtained time after your change. A 169.254 address means no server answered.
  4. Turn Wi-Fi back on.

Lesson 535.3 · Section 4 Setting and Testing a Laptop

535.3.9 Testing one thing at a time

Separate tests of another laptop, the gateway, and a name show whether a fault is on the laptop’s own network, at the gateway, or in the DNS server.

Three tests from a laptop, what each one tests, and the commands.
TestWhat it testsCommands
A peerAnother device on the laptop’s own network, reached through the switch. No gateway or DNS server takes part.ping the peer’s IP address, then arp -a with the same IP address
The gatewayThe router or firewall that leads to every other networkping the gateway’s IP address
A DNS nameThe DNS server’s answer for a name, and then the device at that IP addressnslookup the name, then ping the name

Run each test on its own and record its result before the next. A failure then belongs to one test. When the peer answers and the gateway does not, the laptop’s own network works. Look at the gateway.

Reading ping

ping sends four echo requests, using the Internet Control Message Protocol (ICMP), and prints a line for each.

  • Reply from 192.168.70.1: bytes=32 time<1ms TTL=64: the device at that IP address answered. Time To Live (TTL) is a count each router lowers by one; it plays no part in these tests.
  • Request timed out.: no answer came back. The device may be off or unreachable, or a firewall on it may block the answer.
  • Reply from 192.168.70.141: Destination host unreachable., carrying your own IP address: your laptop found no device at the destination on its own network. The line is not a reply from the destination.
  • Ping request could not find host recorder01.northgate.example. Please check the name and try again.: the name did not resolve to an IP address. No request was sent.

When a peer does not answer: the Windows firewall

Windows Defender Firewall blocks an incoming ping by default: the rule that allows it, File and Printer Sharing (Echo Request - ICMPv4-In), is off unless file sharing or the organization’s policy has turned it on. A ping from one such laptop to another times out even when the path between them works. Before a laptop sends a ping on its own network, it learns the peer’s MAC address with an Address Resolution Protocol (ARP) request, which the firewall does not block. arp -a lists what the laptop learned.

arp -a: a peer on another job that does not answer ping
C:\Users\installer> arp -a 192.168.70.142

Interface: 192.168.70.141 --- 0xc
  Internet Address      Physical Address      Type
  192.168.70.142           00-00-5e-00-53-3c     dynamic
  • Interface: the laptop’s own IP address on that adapter, and a number Windows gives the adapter.
  • Internet Address and Physical Address: the peer’s IP address and the MAC address that answered for it. dynamic means the laptop learned the entry from the network.

An entry with type dynamic, read straight after the ping, shows that the peer answered through the switch, even where its ping timed out. Where nothing answered, the command prints No ARP Entries Found.

Testing a name

nslookup asks the DNS server directly and prints its answer. ping by name asks Windows to resolve the name, normally through the same DNS server, and pings the IP address it receives.

nslookup: a name on another job’s DNS server
C:\Users\installer> nslookup recorder01.northgate.example

Server:  dns01.northgate.example
Address:  192.168.70.10

Name:    recorder01.northgate.example
Address:  192.168.80.20
  • The first Server and Address lines: the DNS server that answered. A server with no name for its own IP address shows UnKnown as its name.
  • Name and the second Address: the name you asked for and its IP address.

A name the server cannot find returns a line ending Non-existent domain. A line reading Non-authoritative answer means the server answered from its memory or from another server; it is not an error.

Lesson 535.3 · Section 5 Wrapping Up

535.3.10 What you covered

An installer reads a laptop’s settings, takes an IP address only from the plan, tests each part of the path on its own, and leaves the laptop on DHCP.

What a device needs to reach the network

The IP address identifies the device; the subnet mask tells it which IP addresses are on its own network; the default gateway carries traffic to every other network; the DNS server turns names into IP addresses. The devices you install use private IPv4 addresses. 127.0.0.1 is loopback and never leaves the laptop. IPv6 addresses are groups of hexadecimal digits separated by colons. Windows lists an fe80:: address on every connected adapter.

Where the settings come from

Reading an address plan

On a /24 network, two IP addresses are on the same network when their first three numbers match. An IP address with a last number of 0 is the network address, and one with 255 the broadcast address. On a /25, /26, or /27 network, take the range from the plan. An unused IP address is on the network and is not the network or broadcast address, the gateway, a reserved address, an address in the DHCP pool, or an address listed against a device. The plan’s holder confirms it.

Setting and testing a laptop

Record the starting settings. Set a static IP address under Settings > Network & internet > Ethernet > IP assignment > Edit > Manual, with the mask, the gateway, and the DNS server. Test the peer, the gateway, and a name in separate commands: ping and arp -a, ping, then nslookup and ping by name. A peer’s firewall may block ping; a dynamic entry in arp -a, read straight after the ping, shows it answered. Restore Automatic (DHCP), check the DNS server assignment row, and prove the lease with ipconfig /renew (or by unplugging and replugging the cord) and ipconfig /all.
